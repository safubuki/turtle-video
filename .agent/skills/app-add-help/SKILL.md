# App Add Help

## スキル読み込み通知

このスキルが読み込まれたら、必ず以下の通知をユーザーに表示してください：

> **App Add Help スキルを読み込みました**  
> アプリケーションの操作体験と完全に一致する「階層アコーディオン＆インライン操作見本ヘルプシステム」を設計・実装・検証します。

---

## 概要

このスキルは、Webアプリやデスクトップアプリに**「ユーザーが迷わず、操作体験と直結した高品質なヘルプ機能」**を追加・刷新するための専門スキルです。

長文テキストを羅列するだけの読みにくいヘルプや、アイコンが末尾に固まってどれが何の説明かわからないヘルプを排除し、以下の設計を決定的に実現します：

1. **操作体験と一致する階層構造**: カテゴリ親アコーディオン（目次機能）＋直接表示項目＋子アコーディオン（詳細調整）。
2. **インライン視覚見本（直結配置）**: 説明文（箇条書き）の直下に、該当するボタンやコントロール見本をインデント配置。
3. **メタ混乱の防止**: アコーディオン開閉ヘッダー枠の見本は排除し、実操作部品のみを見本化。
4. **領域境界の視認性**: `border-2 border-gray-600/80` によるシャープで明瞭なカード外枠設計（未定義CSSカラーのフォールバック事故防止）。
5. **デバイス最適化**: PC（クリックで開閉）/ スマホ（タップで開閉）のレスポンシブ切り替え。
6. **自明な状態記述の全廃**: 「開くと」「閉じています」などの見たらわかる解説を排除し、目的と使い方に集中。
7. **プラットフォーム・Flavor境界**: 特定環境（iOS Safari等）の非対応機能はヘルプ項目ごと自動フィルタリング。
8. **基本ルール・ライセンスの完全一致**: 推奨動作環境、注意事項、本体ライセンスおよび全依存ライブラリのライセンス一覧を網羅。

## 役割分担

| 領域 | 担当 | 処理内容 |
| :--- | :--- | :--- |
| **機能把握・静的解析** | `scripts/help_system_tool.py scan` | UIコードからボタン、アイコン、入力項目、セクションを自動抽出 |
| **情報設計・動線判断** | AI | 抽出結果から主要カテゴリ・基本操作・詳細調整の階層を設計 |
| **雛形スキャフォールド** | `scripts/help_system_tool.py scaffold` | ベストプラクティスに準拠したヘルプ定義スケルトンを生成 |
| **UIコンポーネント実装** | AI | 実画面と完全一致する操作見本トークン・アコーディオンモーダルの実装 |
| **品質・UXルール監査** | `scripts/help_system_tool.py validate` | 140文字制限、孤立アイコン検出、アコーディオン枠見本の混入防止を自動検証 |
| **テスト・保守性確保** | AI | 導入文長、Flavor境界フィルタリング、Hooks耐久性のユニットテストを作成 |

## 手順

### Step 1: 既存アプリのUI機能と操作要素を抽出する

アプリのソースディレクトリを指定してスキャンを実行し、どのようなセクションや操作ボタンがあるかを抽出します。

```bash
python scripts/help_system_tool.py scan --src src --output help-features.json
```

AIは抽出結果（`help-features.json`）を読み、以下を整理してユーザーに提案します：
- ヘルプのセクション構成（例: 画面や主要カード単位）
- 各セクション内の「基本アクション」「全体設定」「個別設定」の分類

### Step 2: ヘルプデータ定義のスケルトンを生成する

スキャン結果をもとに、高品質ヘルプのデータ定義スケルトンを生成します。

```bash
python scripts/help_system_tool.py scaffold --scan-file help-features.json --output src/constants/helpContent.json
```

生成された定義をベースに、AIがアプリの文脈に沿って以下の情報を拡充します：
1. **各項目の説明文（description）**: 140文字以内で「何のための機能か（目的）」を端的に説明。
2. **箇条書き（bullets）**: 操作手順や仕様を `・` 付きの箇条書きに分散。
3. **インライン視覚見本（visuals）**: 各箇条書きの直下に紐付ける操作部品IDを指定。
4. **基本情報項目**: 動作環境、注意事項、ライセンス表記を追加。

### Step 3: UIコンポーネント（HelpModal）を実装する

[references/help-design-principles.md](references/help-design-principles.md) に基づき、モーダルUIコンポーネントを実装します。

- **親アコーディオン**:
  ```tsx
  <div className={`rounded-2xl border-2 transition-colors overflow-hidden ${
    isOpen ? 'border-gray-500/90 bg-gray-900/95 shadow-xl' : 'border-gray-600/80 bg-gray-800/40 hover:border-gray-500/80'
  }`}>
  ```
- **インライン見本レンダラー**:
  箇条書きをループする際、`bullet.visuals` があればその行の直下に `renderVisualToken` で描画。使用済み visual は Set で保持し、カード最下部での重複描画を防止。
- **PC/スマホ表記切替**:
  `inline md:hidden`（タップで開閉）と `hidden md:inline`（クリックで開閉）でレスポンシブに表記を出し分け。
- **一括開閉ボタン**: 「すべて開く」「すべて閉じる」を上部に配置。

### Step 4: ヘルプ定義の品質を自動検証する

スクリプトの `validate` コマンドで、UXルールおよびアクセシビリティルールを検証します。

```bash
python scripts/help_system_tool.py validate --file src/constants/helpContent.json
```

- 警告やエラーが出た場合は、指示に従って導入文の短縮や見本のインライン化、アコーディオン見出し見本の削除を行います。

### Step 5: 自動テスト（Unit Tests）を整備する

ヘルプが将来の改修で壊れないよう、テストを作成します：
- 導入文が140文字以内に保たれていること
- 重要な用語や数値（単位・刻み幅）が含まれていること
- 定義された視覚トークンが漏れなくレンダリングされること
- モーダルの開閉や全展開で Hooks エラーが発生しないこと

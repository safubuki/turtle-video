# 情報アーキテクチャと提示順序

「何を、どの順で見せるか」を決めるためのリファレンス。いきなり詳細を出さず、段階的に理解が積み上がる流れを設計する。

---

## 1. 基本原則: 逆ピラミッド + 段階的開示

### 逆ピラミッド（Inverted Pyramid）

ジャーナリズム由来の構成法。**結論を最初に置き、詳細を後段に置く。**

```
1. 結論 / 価値       ← 3秒で伝わる。ここで離脱しても要点は伝わる
2. 裏付け / 具体     ← 興味を持った人が読む
3. 詳細 / 背景       ← 深く知りたい人だけが読む
```

Web は逐次読解されない。ユーザーはスキャンし、価値が見えなければ離脱する。**最も重要な情報を最初のスクロールなし領域に置く。**

### 段階的開示（Progressive Disclosure）

NN/g が体系化した手法。**高頻度で使う機能を主画面に置き、低頻度・上級者向けの機能を二次画面へ送る。**

効果は「学習しやすさの向上」と「エラー率の低下」。ユーザーは一度に処理する選択肢が減るぶん、迷いと誤操作が減る。

| 手法 | 使いどころ |
|------|-----------|
| アコーディオン | FAQ、詳細仕様、補足情報 |
| 「詳細を見る」リンク | 一覧 → 個別詳細 |
| ツールチップ | 用語の補足、任意の説明 |
| ステップフォーム | 入力項目が多い登録・購入 |
| 「詳細設定」の折りたたみ | 上級者向けオプション |

> ⚠️ **注意**: 隠した情報は発見されにくくなる。**必須の情報を段階的開示の裏に隠さない。** 隠してよいのは「大半のユーザーには不要」なものだけ。

## 2. 認知負荷を決める要因

### Hick の法則（選択肢の数）

選択肢が増えるほど決定時間は増える（対数的に増加）。

**実務上の含意**:
- グローバルナビは 5〜7 項目に抑える
- 1画面のプライマリアクションは 1 つ
- 選択肢が多い場合はカテゴリでグルーピングして階層化する

**限界**: この法則は「等質な選択肢からの単純選択」を前提とする。視覚的階層で優先度が明示されていれば、項目数が多くても実際の負荷は小さくなる。**「項目数を減らせば必ず良い」という単純な話ではない。**

### Fitts の法則（ターゲットへの到達時間）

到達時間は「距離」と「サイズ」で決まる。遠く小さいものほど押しにくい。

**実務上の含意**:
- 主要アクションは大きく、ユーザーの現在位置の近くに置く
- 画面の四隅・端は「無限の幅」を持つため押しやすい（モバイルの下部ナビが有効な理由）
- 破壊的アクションは、逆に**あえて近づけない**。誤クリックを設計で防ぐ

### Miller の法則（7±2）の扱い

「人間の短期記憶は 7±2 個」は広く引用されるが、**UI 設計への直接適用は誤用**とされることが多い。元の研究は「記憶すべき無関係な項目」の話であり、画面に**表示され続けている**項目には当てはまらない。

> ナビを 7 項目に抑える根拠は Miller ではなく Hick の法則と視覚的スキャン効率にある。

## 3. 視線の流れ

| パターン | 発生条件 | 設計への反映 |
|---------|---------|------------|
| **F パターン** | テキスト主体で階層が弱いページ | 各段落の冒頭に情報を寄せる。左側にキーワードを置く |
| **Z パターン** | 要素が少ないLP・ヒーロー領域 | 左上ロゴ → 右上ナビ → 中央訴求 → 右下CTA |
| **レイヤーケーキ** | 見出しと本文が明確に分かれた構造 | 見出しだけで内容が分かるようにする |

**最重要**: F パターンは「良いパターン」ではなく、**階層設計が弱いときに発生する読みにくさの兆候**。見出し・余白・視覚的強弱で流れを設計すれば、ユーザーは F 字ではなく意図した順序で読む。

## 4. ページ種別ごとの推奨セクション順序

### ポートフォリオ / 個人サイト

「この人が何者で、何ができて、その証拠は何か」の順に積む。

```
1. ヒーロー       誰で、何をする人か（1文）+ 主要CTA
                  例: 「フロントエンド開発者。触って気持ちいいUIを作ります」
2. 概要 / About   もう少し詳しい人物像、専門領域、価値観
3. 実績 / Works   具体的な成果物。★ここが証拠の中核
4. スキル         使える技術（実績の裏付けとして）
5. 経歴           時系列の詳細（興味を持った人向け）
6. コンタクト     次の行動への導線
```

**順序の根拠**: 「誰か」が分からないまま実績を見せられても評価軸が定まらない。逆に人物像だけで証拠がなければ信用されない。**主張 → 証拠**の順に置く。

### ランディングページ / 製品ページ

```
1. ヒーロー         解決する課題と価値（What + Why）
2. 社会的証明       ロゴ・利用者数・評価（早めに信頼を作る）
3. 主要ベネフィット 3つ程度。機能ではなく「得られる結果」
4. 機能詳細         How。ここで初めて具体的な仕組み
5. 事例 / 証言      具体的な成功例
6. 料金             判断に必要な情報
7. FAQ              残った不安の解消
8. 最終CTA          決めた人の受け皿
```

**原則**: ベネフィット（結果）を先、機能（手段）を後。「何ができるか」より「自分に何が起きるか」が先に伝わる必要がある。

### ダッシュボード / 管理画面

```
1. 全体サマリ     健全性が一目で分かる主要指標
2. 要対応         異常・アラート・承認待ち（行動が必要なもの）
3. 詳細データ     テーブル・グラフ
4. 設定           最も低頻度。奥に置く
```

**原則**: 「見る」より「気づいて動く」を優先。異常があるときはそれが最上位に浮上する設計にする。

## 5. 情報の粒度をそろえる

同じ階層に**抽象度の違うものを並べない**。これが崩れると理解の流れが途切れる。

```
🚫 悪い例（粒度がバラバラ）
   ・機能一覧
   ・料金
   ・ボタンの色をカスタマイズする方法   ← 急に詳細すぎる
   ・会社概要

✅ 良い例（同じ粒度）
   ・機能
   ・料金
   ・カスタマイズ
   ・会社概要
```

---

## 6. 最初のスクロールなし領域で答えるべき3つの問い

ユーザーは数秒で「留まるか去るか」を判断する。ヒーロー領域は次の3つに答える：

1. **これは何か**（What）— サービス/人物の正体
2. **自分に関係あるか**（Why me）— 解決される課題、対象読者
3. **次に何をすればいいか**（What next）— 明確な単一のCTA

> 🚫 抽象的なキャッチコピーだけを置かない。「未来を、デザインする。」は何の情報も伝えない。

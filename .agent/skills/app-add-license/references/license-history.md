# Turtle Video のライセンス対応履歴と公開者の方針

記録日: 2026-09-27。数値は当時のスナップショットであり、次の作業では現物から再計算する。詳しい人間向けの説明はリポジトリの `Docs/specs/2026-09-27_license-compliance-guide.md` にある。

## 公開者の状況と懸念

- 個人用に作ったアプリを、公開・リリース方法の学習を兼ねて、無償の OSS として公開している。現時点では事業化していない。
- GPLv3 を想定し、ライセンス条件と利用 OSS の一覧は既に明記していた。この整備は有益だが、配布される第三者コードの原文告知や特許の確認とは役割が違う。
- 個人で関連特許を網羅的に確認することはできない。具体的な指摘には速やかに対応したい。機能改善だけで直ちに問題が解消すると決めず、対象の権利と実装を確認し、必要なら停止・変更・相談を選ぶ。

## 対応前にできていたこと

- ルート `LICENSE` に GNU GPLv3 本文と「version 3 or any later version」の告知があり、ソースヘッダーも `GPL-3.0-or-later` だった。
- README とアプリ内ヘルプで GPL と OSS 依存ライセンス名を案内していた。
- GitHub Pages 向けの `npm ci`、`npm run build`、`dist/` アップロードの流れがあった。

## 今回補ったこと

| 項目 | 以前の不足 | 対応 |
| --- | --- | --- |
| 本体の SPDX 表記 | `package.json` / `package-lock.json` のルートが `GPL-3.0` で正本と不一致 | `GPL-3.0-or-later` に統一。これは既存の選択を明確化したもので、GPLv3 を含む |
| README の特許説明 | GPLv3 が第三者特許から広く守るかのように読める余地 | 貢献者による特許ライセンスの規定と第三者特許の非侵害保証を区別 |
| ヘルプの依存集計 | ロックファイルと件数が不一致 | ルートを除く 677 エントリのライセンス別件数に合わせ、一覧の対象を明示 |
| 配布物の第三者告知 | ライセンス名一覧はあったが、バンドルされたパッケージの著作権表示・許諾文が `dist/` に無かった | ビルドで `THIRD_PARTY_LICENSES.txt` を生成し、`LICENSE.txt` とともにヘルプからリンク。検証ビルドでは 17 パッケージ |

## 告知生成の範囲と限界

`scripts/generate-third-party-licenses.mjs` は配布ソースマップからパッケージを検出し、生成コードに関係する `vite`、`vite-plugin-pwa`、`tailwindcss` を明示的に加える。各パッケージのトップレベルの `LICENSE` / `LICENCE` / `COPYING` / `NOTICE` 系ファイルを含め、必要なファイルやメタデータが無ければビルドを失敗させる。ソースマップに現れない新しい生成方式、手動コピー、静的素材、CDN 素材は別に点検する。

当初提案された `license-checker-rseidelsohn --files ... --out ...` の例は、個別ライセンスファイルのコピーとレポート出力を組み合わせたもので、単一の原文告知ファイルをそのまま作るものではなかった。`--production` だけでは PWA 生成物も見落とし得る。今回の自動生成方式も全件・全権利を保証しない。

## 次回の確認と相談

- 依存・素材・配布形態を変えたら、原文条件、告知、対応するソースコードの提供方法、公開先での到達性を再確認する。
- PWA のオフライン用キャッシュに両告知ファイルが含まれるかは未検証。オフライン配布を強める際に確認する。
- GPL の `-or-later` を変更する場合は公開者の方針変更として扱い、既存告知や寄与者の権利を確認する。
- 具体的な特許等の指摘は、権利番号・国・請求項・対象実装と版を保存して個別に検討する。法的な認否と外部への連絡は公開者が決める。

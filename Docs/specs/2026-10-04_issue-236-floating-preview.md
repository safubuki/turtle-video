# スマホの追従ミニプレビュー（Issue #236）

## 現状と目的

スマホでは通常プレビューが編集欄の下にあり、編集後の映像確認にページ移動が必要。編集位置を維持したまま再生・位置移動を確認できる補助UIを追加する。

## 要件と設計

| 要件 | 実装方針 |
| --- | --- |
| スクロールに追従する小さな入口 | モバイルレイアウト（1024px未満）の固定ボタン。素材があり、通常の映像領域が画面外のときだけ表示 |
| 編集位置を保持 | モーダル化やページスクロールを行わず、固定パネルを開閉。手動操作のフォーカス移動は `preventScroll`。自動復元時は編集中の入力欄のフォーカスを維持 |
| 再生・停止・シーク・±5秒 | 通常プレビューの既存コールバックを使用。移動先は0〜総尺へ制限 |
| 二重再生と描画負荷の抑制 | 既存Canvasを1個だけ使用。一定のportalコンテナを通常／ミニの表示枠へ移す。Canvas、コンテキスト、解像度、映像・音声の要素、再生ループを作り直さない |
| 通常プレビューが見える場合 | 開いていた意図を保持してパネルを一時的に取り外し、Canvasを通常枠へ戻す。画面外へ戻ったらボタンを経由せずミニ表示を復元。通常の再生は同じ経路で継続 |
| 書き出し中 | 開いていた意図も解除し、補助ボタン／パネルをアンマウントしてCanvasを通常枠へ戻す。監視も停止。自動解除で停止コールバックを呼ばず、exportを中断しない |
| 手動で閉じる場合 | 再生を一時停止し現在位置を保持。開いていた意図を解除し、再スクロール時も自動では開かない |
| スワイプ保護 | Issue #233のシーク入力処理を共通コンポーネントへ抽出し、通常／ミニで共有。縦パン・複数指・キャンセルで値を反映しない |
| 可視性と操作性 | safe areaを考慮した配置、44px以上の操作領域、縦動画はcontain、短い横画面は映像＋見出しと操作を横並び。タイミング打ちバーは利用時だけResizeObserverで実測し、その高さを避ける |

### 実装の境界

- standard / apple-safariの共通UI。描画・exportエンジンと保存スキーマは変更しない。
- portalの描画先要素は一定に保つ。表示先を変更するためにportal自体のtargetを切り替えるとCanvasが再生成されるため禁止。
- Canvasのbacking解像度をミニ表示サイズへ落とさない。開閉ではwidth/heightを代入しない。
- 補助表示用のCanvasコピー、captureStream、video/audio、AudioContext、rAF、interval、独自再生時計を追加しない。
- 不要時は補助コントロールを描画しない。IntersectionObserver非対応時は通常プレビューを利用する。
- 開閉状態はセッション限定。保存・書き出し内容に含めない。
- 通常映像の画面内復帰だけを一時非表示として扱う。書き出し・モーダル・PC幅・素材消失・バックグラウンドでは開いていた意図を解除する。

# 手動保存を3枠に拡張する仕様書

作成日: 2026-09-24

## 概要

手動保存を①②③の3枠に増やし、同じブラウザ内の IndexedDB にプロジェクトを保持する。保存・読込・名前変更・個別削除・一括削除を保存画面から行う。プロジェクトのファイル書き出し・ファイル読み込みは追加しない。

## 現状と互換性

- IndexedDB `turtle-video-db` の `projects` に `auto` と `manual` の2キーがある。旧 `manual` は①としてそのまま読む。DBを消したり既存の保存データをコピーしたりしない。
- ②③は同じ `projects` に `manual-2` / `manual-3` で保存する。`auto` は引き続き独立した自動保存で、3枠には数えない。
- 保存済み素材は ArrayBuffer を含む。3枠で保存容量を使うため、容量不足は従来の診断・回復画面を維持する。保存失敗時に対象枠の旧データを消さない。
- standard と apple-safari の双方で同じ3枠を使う。保存データの既存フィールドと読込後の編集・再生・書き出し経路は変更しない。

## 要件と決定事項

| ID | 仕様 |
|---|---|
| R1 | 保存画面に①②③を常に表示し、空枠は「未保存」と示す。保存先を明示的に選択する。 |
| R2 | 空枠は確認なしで保存する。既存枠は枠番号・タイトル・日時を示して上書きを確認し、キャンセルでは何も変更しない。 |
| R3 | 保存成功後、モーダルは開いたまま一覧へ戻り、枠のサムネイル・タイトル・動画の長さ・保存日時を更新する。保存と一覧更新が終わるまでは二重操作を無効化する。 |
| R4 | サムネイルは保存時の小さな JPEG を保存メタデータに持つ。現在のプロジェクトポスターが有効なら利用し、それ以外ではプレビューから取得を試みる。素材なし・取得失敗時はプレースホルダーを表示し、保存自体は続行する。 |
| R5 | 動画の長さは本編と有効なエンドロールの合計秒数を保存時に確定し、`分:秒` で表示する。旧データは素材・エンドロールから算出する。 |
| R6 | ユーザー向けタイトルは空を許可する。保存後にタイトルを押して編集できる。空は「無題のプロジェクト」と表示する。動画内のタイトル設定とは独立する。前後の空白を除去し、最大80文字とする。 |
| R7 | 内部識別子 `projectId` は初回保存で生成し、名前変更・同じ枠への上書きで維持する。旧①は決定的な識別子を補完する。UIで表示する①②③は枠番号で、識別子とは別。 |
| R8 | 保存済み枠を選んで読込できる。現在の編集内容がある場合の読込確認は従来どおり行う。自動保存も従来どおり読込可能。 |
| R9 | ①②③を個別に削除できる。削除対象を明示して確認し、成功後のみ空枠表示に戻す。 |
| R10 | 「手動保存データのみ削除」は埋まった①②③のみを確認後に削除する。自動保存を消す従来の「すべての保存データを削除」はその下の別操作として明示的に残す。両ボタンは同じ高さとし、ゴミ箱アイコンを付ける。 |
| R11 | タイトル変更は保存済みプロジェクトのメタデータのみを更新し、動画素材を再シリアライズしない。更新失敗時は元の表示に戻し、通知する。 |

## 画面と操作

- 保存画面の手動保存エリアに①②③のカードを縦に並べる。各カードは左に大きめの7:5サムネイル、右に小さめのタイトル、動画尺・保存日時、その下に保存・読込・削除ボタンを置く。カードの縦幅を抑え、狭い画面ではボタンを折り返す。
- 未保存枠でも動画尺・保存日時の行の高さを確保し、操作ボタンの位置を保存済み枠と揃える。カードのボタンは保存済みでも「保存」と表示し、押した後に上書き確認を行う。共通の大きな「保存先を選んで手動保存」「読み込み」ボタンと各選択画面は置かず、各枠のボタンから直接操作する。
- 自動保存間隔と自動保存の状態を1枚のカードにまとめる。上段に間隔、下段にサムネイル、自動保存ラベル、状態・日時、読込・削除ボタンを置く。自動保存と手動保存のサムネイル枠は同じ 7:5 比率とし、右側の情報に対して縦方向の中央へ揃える。状態文の行数で画像が縦に伸びないようにする。自動保存に書込ボタンは置かない。自動保存の削除も確認する。
- タイトルをクリックまたはタップすると入力欄に変わる。Enter または「保存」で確定、Escape または「キャンセル」で破棄する。空タイトルも確定できる。フォーカスとラベルを提供する。
- 保存先の選択、上書き確認、読込確認、削除確認はモーダル内で行う。確認画面では対象の番号とタイトルを表示する。
- 自動保存の日時・状態・再始動・容量診断・容量不足時の復旧導線は維持する。

## データ契約

```ts
type ManualSaveSlot = 'manual' | 'manual-2' | 'manual-3';
type SaveSlot = 'auto' | ManualSaveSlot;
interface ManualProjectSummary {
  slot: ManualSaveSlot;
  projectId: string;
  title: string; // 空文字を許可
  savedAt: string;
  durationSec: number;
  thumbnailDataUrl: string | null;
}
```

`ProjectData` に上記メタデータを任意フィールドとして加え、旧 `manual` は読み取り時に補完する。一覧表示では素材バイナリを毎回複製しないよう、同じ IndexedDB 内に軽量なメタデータ用ストアを置き、プロジェクト本体と同一トランザクションで更新する。自動保存の日時とサムネイルもこのストアに置く。旧データの初回表示では①と自動保存を一度ずつ読み、メタデータを補完する。サムネイルは表示用に横幅320pxまで縮小する。DBのスキーマ更新に失敗した場合、旧保存データを削除しない。

## 受け入れ条件

1. 旧 `manual` が①に表示され、読込・上書き・名前変更・削除できる。
2. ①②③に異なるプロジェクトを保存し、再起動後もタイトル・サムネイル・尺と本体が対応する。
3. 上書き・個別削除・手動一括削除をキャンセルした場合、保存データは変わらない。
4. 手動一括削除後も `auto` は残り、別の全件削除では `auto` も消える。
5. 保存失敗・容量不足・タイトル更新失敗で既存の枠を失わない。
6. standard / apple-safari 双方で読込後の再生・書き出しに影響がない。

## 実装計画

### Phase 1: 永続化と互換性

`SaveSlot`、軽量メタデータ、IndexedDB の保存・一覧・個別/一括削除、旧①補完を実装する。保存本体とメタデータの整合性、旧データ、失敗時の保護をテストする。

### Phase 2: ストアとサムネイル

`projectStore` に枠指定保存、一覧更新、名前変更、個別/手動一括削除を加える。既存の保存キューと容量診断を維持し、保存時の動画尺とサムネイルを確定する。ストアの回帰テストを追加する。

### Phase 3: 保存画面

3枠カードと選択・上書き・削除確認、タイトル編集を実装する。自動保存・旧読込・DB復旧画面とモバイル操作を確認する。

### Phase 4: 統合と文書

関連するヘルプと `turtle-video-overview` を更新する。関連テスト、型チェック、製品ビルドを実行し、保存データと自動保存の境界を確認する。

## 追加で考慮する点

- ブラウザのストレージ上限は端末ごとに異なり、3枠を必ず満杯まで保存できるわけではない。空き容量の診断と既存データを保持した失敗通知が必要。
- ブラウザデータの削除やプライベートブラウズでは保存が失われ得る。外部バックアップは今回の仕様に含めないため、保存画面の説明を明確にする。
- 複数タブで同じ枠を操作した場合は、実行直前に最新の枠情報を読み直して確認対象との食い違いを防ぐ。

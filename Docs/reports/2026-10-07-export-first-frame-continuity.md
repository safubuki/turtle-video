# 書き出し動画の先頭フレームの連続性

**日時**: 2026-10-07  
**深刻度**: Minor（映像品質）  
**対象**: standard（Android / PC）の WebCodecs 書き出し

## 現象と期待動作

ユーザーから、複数のPCで書き出した動画の開始時にサイズ・位置が一瞬ずれたように見えるとの報告。最初のフレームも、以降と同じタイムライン・倍率・位置・フェード・キャプションで描画されることを期待する。

## 観測事実と原因

- 修正前の `createExportVideoFrame` は、ポスターがある場合だけ `frameIndex === 0` を別Canvasへ描き直していた。その際、確定した描画スロットの `source` を無視していた。
- standard の通常Canvasエンコードと不足フレーム補完から、同関数にプロジェクトポスターの ImageBitmap が渡る。TrackProcessorの通常フレームはこの差し替えを通らない。
- `resolveAutoProjectPosterCaptureTime` は先頭黒クリア帯を避けるため、通常の自動ポスターを0.06秒以降に撮る。手動ポスターは任意のタイムライン位置を撮る。
- 修正前のコードで、先頭スロットの同一性とスナップショットなしの先頭描画を検証する2テストが失敗し、先頭だけ別Canvasになることを再現した。Canvasは要素の深い比較では同じ寸法なら一致してしまうため、`toBe`で参照を検証する。

**原因判断**: ポスター差し替えは、先頭フレームの倍率・絵・フェードを以降と不連続にする到達可能な不具合。ズーム中は0秒とポスター取得時刻で実効倍率が異なるため、小さなサイズの跳びにもつながる。ズームなしでも、動く動画や任意時刻の手動ポスターでは絵が跳ぶ。発生頻度・今回のユーザーのMP4との一致は、実ファイル未提供のため未確定。

## 修正

1. 先頭ポスター差し替えと、それだけに使う ImageBitmap 読み込みを削除。
2. 全フレームで描画済みスナップショットを優先し、未提供の場合は通常のCanvasから VideoFrame を生成。
3. MP4のcovrへのポスター埋め込み、先頭のキーフレーム指定、時刻・総尺・CFR・音声・再生時計・backpressure・スロット固定を維持。
4. 仕様、exportの型コメント、overviewの13-269へ追記。13-146の先頭KF差し替えは今回廃止した経緯を明記。

カバーアートを使うビューアには設定画像を渡す。映像からサムネイルを抽出するOSでは、設定ポスターと異なるアイコンになる場合がある。既存の書き出し済みMP4は変更されないため、修正後のアプリで再書き出しする。

## 検証

- 修正前の既存MP4カバーアート・ズームテスト: 13件成功。
- 修正前の追加再現テスト: 2件失敗、先頭以外は成功。
- 修正後の関連テスト: 13ファイル・193件成功。先頭/次スロット、スナップショットなし、VideoFrameのtimestamp/duration/alpha、covr追加後のmdat不変、ズーム、分割・継承、端点シーク、リングバッファ、フレーム時刻、書き出しruntime、両flavorの描画を確認。
- `tsc`、`vite build`、`scripts/generate-third-party-licenses.mjs`: 成功。既存のチャンクサイズ等の警告あり。
- 全体テスト（`vitest run --maxWorkers=2`）: 153ファイル・1925件のうち1918件成功、4件失敗、3件はワーカーのヒープメモリ不足で未完了。
- 4件の失敗: `aiModalPopstate.test.tsx` のAPIキー警告1件、`sectionHelp.test.ts` の旧BGM文言1件、`sectionHelpModal.test.tsx` のAPIキー警告2件。変更前HEAD `f279bc32ef9ffb3c9cf26697ee56b73997dececf` のソースを隔離し、同じenvDirで3ファイル・34件を実行すると、同じ4件が同じ理由で失敗した。今回の差分による退行ではない。
- ワーカー異常終了: `turtleVideoExportWiring.test.tsx` の3件。単独・1ワーカーでもヒープメモリ不足が再現し、上記の変更前HEADの隔離コピーでも同じヒープメモリ不足を確認した。今回の差分による退行ではない。この既存テスト問題は今回の映像修正の範囲に含めていない。
- 差分レビュー: 指摘なし。映像の先頭生成以外に再生・音声・保存契約を変える処理は追加していない。
- 未確認事項: この環境に操作可能なブラウザーがなく、実WebCodecsによるMP4再生とOSサムネイルの表示は未検証。

## 実機の受け入れ確認

1. 先頭が動画のプロジェクトを、自動サムネイルで書き出す。ズームなし/イン/アウト、縦/横、トリム済み・倍速を確認する。
2. 手動サムネイルを先頭以外へ設定し、同じプロジェクトを書き出す。
3. 新しいMP4の先頭数フレームを停止・コマ送り・繰り返し再生し、ポスターの絵が一瞬挿入されないことを確認する。フェードインと先頭キャプションもタイムラインどおりか確認する。
4. covrを読むビューアのサムネイルを確認する。Windowsエクスプローラー等の映像抽出とキャッシュの挙動は、映像の連続性とは別に記録する。
